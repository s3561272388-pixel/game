# 05 · 错误报告模板与修复循环

> 第 3 步（我做可玩性检测、生成错误代码报告）与第 4 步（GPT-6 修 Bug）之间的接口规范。
> 目标是让 GPT-6 **不需要问你任何问题就能开始修**，并且修完后你能机械地判断"真的修好了"。

---

## 1. Bug 分级

| 级别 | 定义 | 典型例子 | 处理要求 |
|---|---|---|---|
| **S0** | 致命：结算错误、非确定性、无法开局、卡死/死状态 | 同种子结果不一致；金币扣了物品没到手；背包满导致无法继续；战斗永远打不完 | 立即修，阻塞一切 |
| **S1** | 高：数值与规格不符、非法状态、数据错误、引擎/表现未分离 | 伤害差 1；护甲结算顺序反了；协同加成加给了自己；买了物品放不下；`data` 校验失败 | 本轮必须修 |
| **S2** | 中：平衡/体验指标未达标、性能不达标、告警 | 难度曲线偏离设计区间；单件伤害占比超标；死件过多 | 本轮应修，或明确记录为已知问题并给出计划 |
| **S3** | 低：文案、命名、格式、编辑器告警 | 错别字；tooltip 文案与数值表述不一致 | 可延后，批量处理 |

**门禁**：无 S0、无 S1、无 FAIL 检查项 → 方可进入下一阶段。

## 2. 报告模板（`tools/qa-check.mjs` 自动生成，此处是字段说明）

每条 Bug 必须包含以下字段，缺一不可。**没有"复现步骤"和"实际输出"的 Bug 报告等于没写**——
GPT-6 只能靠猜，而猜错会引入新 Bug。

```markdown
### [S1] 战斗结算：伤害比参考裁判少 1 点

- **复现步骤**
  ```powershell
  node tools/sim-dump.mjs --demo --out out
  node tools/diff-test.mjs --evals out
  ```
- **期望**：与参考裁判逐 tick 完全一致（差异 0 个）
- **实际**：`tick 12，第 1 方第 3 号物品：裁判 伤害7，游戏 伤害6`
- **定位**：`packages/engine/src/battle.ts:142`（由 diff-test 报告的 tick 反查）
- **根因**（由修复者填写）：……
- **修法提示**：裁判是「先乘所有加成与暴击 → `Math.floor` → 再扣护甲」。
  若先扣护甲再取整，数值会差 1。
- **同类风险**：治疗量、护甲获取是否也有同样的取整顺序问题？（需一并检查）
- **验证方式**：修完重跑上面两条命令，必须输出「存在差异 0 个」
```

## 4. 修复循环的标准动作

### 第 1 轮：止血
1. 按 S0 → S1 → S2 排序。
2. 先修 S0。S0 未清零前不要碰 S2。
3. 每条 Bug 都要能复现。**复现不了就停下来问，不要猜**。

### 第 2 轮：回归
```powershell
node tools/validate-data.mjs
node tools/run-balance.mjs --runs 300
node tools/qa-check.mjs
node tools/diff-test.mjs --evals <目录>
```
要求：报告的 `结论` 一行从"未通过"变成"通过"，且 S0/S1 归零。

### 第 3 轮：防复发
对每个 S0/S1，问三个问题并补上对应的自动化检查：
1. 这个错误能被 `validate-data` 抓住吗？不能就加一条校验。
2. 能被 `diff-test` 抓住吗？不能就补一个 eval 用例。
3. 能被单测抓住吗？不能就补一个单测。

> 这一步是让 Bug 数量**单调下降**的关键。只修不复盘的团队会在同一个坑里反复摔。

### 收敛判据
连续两轮 `qa-check` 都通过、且没有新增 S0/S1 → 收敛，可以进入内容扩充阶段。

## 6. 反面模式（明确禁止）

| 反面模式 | 为什么禁止 | 正确做法 |
|---|---|---|
| 改 `tools/engine.mjs` 让差分测试通过 | 裁判是规格的可执行版本，改它等于改考试答案 | 改游戏引擎 |
| 改 `data/rules.json` 的 `qaThresholds` 让指标通过 | 阈值是验收标准，不是调参对象 | 改数值或改设计；确需改阈值必须留痕并说明理由（见 `docs/04 §2.1`） |
| `try/catch` 吞掉异常 | 把崩溃变成算错，更难查 | 让错误抛出，并在 UI 层给用户可读提示 |
| 用默认值兜住非法状态 | 掩盖真实缺陷 | 显式校验并拒绝非法输入 |
| 一次改一大堆再验证 | 出问题无法定位是哪一处 | 一次一类，改完立刻回归 |
| 只贴"已修复"不贴输出 | 无法证伪，Bug 会留到下一轮 | 必须贴命令与真实输出 |
| 把 `Math.random()` 换成"固定种子但每次调用都重置" | 看起来确定，实际不随 seed 变化 | 用 `mulberry32(deriveSeed(...))`，每个阵营一条流，且流绑阵容指纹 |
